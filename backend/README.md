# CodeBug API

Python 3.11+, FastAPI, SQLite. Клиент Flutter получает задания и отправляет выбранную строку; сервер проверяет её, сохраняет попытку и начисляет XP. База создаётся автоматически в `backend/data/codebug.sqlite3` из `seed.json`. Данные не теряются при перезапуске.

## Запуск

Из папки проекта:

```sh
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
backend/.venv/bin/python -m uvicorn app:app --app-dir backend --host 127.0.0.1 --port 8000
```

- API: http://127.0.0.1:8000/api/health
- Интерактивная документация: http://127.0.0.1:8000/docs
- Если существует `build/web`, сервер также раздаёт Flutter-приложение на http://127.0.0.1:8000.
- Переменные окружения: `CODEBUG_DB` — путь к базе; `CODEBUG_ORIGINS` — список разрешённых web-origin через запятую. По умолчанию только localhost/127.0.0.1 на портах 8000 и 8765.

## API

| Метод | Путь `/api` | Назначение |
|---|---|---|
| POST | `/auth/register` | Создать аккаунт: email, password, name |
| POST | `/auth/login` | Вход: email, password |
| POST | `/auth/logout` | Отозвать текущий токен |
| GET | `/me` | Профиль, XP, попытки, решённые задания, активность |
| PATCH | `/me` | Имя и отметки read/hinted; XP менять запрещено |
| DELETE | `/me/progress` | Сбросить учебный прогресс текущего пользователя |
| GET | `/exercises` | Задания без правильной строки и разбора |
| POST | `/exercises/{id}/attempts` | Проверка: line (с 1), уникальный request_id |
| GET | `/leaderboard` | Первые 50 участников: имя, XP, признак you |

Кроме регистрации, входа и health, запросы требуют `Authorization: Bearer <token>`. Пример ответа успешного решения: `correct`, `awarded_xp`, `profile`, `solution`. Неверная попытка не раскрывает solution. Повтор с тем же request_id не создаёт ещё одну попытку; изменение тела при том же ID возвращает 409.

## База данных и правила

- `users`: email, имя, соль и scrypt-хеш пароля.
- `sessions`: SHA-256-хеш непрозрачного случайного токена, срок действия 7 дней.
- `exercises`: серверный каталог, включая ответы. Сидирование добавляет только отсутствующие ID; существующие записи не перезаписываются.
- `attempts`: все проверки, уникальность `(user_id, request_id)`.
- `completions`: первые правильные решения, уникальность `(user_id, exercise_id)`; источник XP и серии.
- `marks`: прочитанные уроки и подсказки; отметки объединяются между устройствами.
- `auth_limits`: ограничение входа/регистрации — 40 запросов с IP за 15 минут.

Транзакция `BEGIN IMMEDIATE` защищает начисление при одновременных запросах. XP и даты определяет сервер. Учебный день — UTC. SQLite работает в WAL-режиме, foreign_keys включены. Изменение пользователя через переданный ID не предусмотрено: ID извлекается из серверной сессии.

## Проверки

```sh
backend/.venv/bin/pip install -r backend/requirements-dev.txt
cd backend
.venv/bin/python -m pytest -q
```

Проверяются авторизация, валидация, выход и истечение сессий, отсутствие ответов в каталоге, начисление XP, повтор запросов, одновременные попытки, изоляция пользователей, повторный вход, перезапуск, сброс, рейтинг, CORS и ограничение запросов.

## Развёртывание

Текущая конфигурация предназначена для локальной учебной демонстрации и одного экземпляра API. Для телефона нужен доступный ему адрес сервера; `127.0.0.1` на телефоне относится к самому телефону. Android Emulator использует `10.0.2.2:8000`. В release Android нужен HTTPS; HTTP разрешён только в debug-манифесте. Для iOS укажи HTTPS URL через `--dart-define=API_BASE_URL=https://...`.

Для публичного сервера настрой HTTPS/reverse proxy, точный CORS, резервные копии базы и управление процессом. Не доверяй произвольным forwarded-заголовкам при настройке proxy. Верификация email, восстановление пароля и админ-панель пока не реализованы. Никакой произвольный код на сервере не исполняется. SQLite можно заменить PostgreSQL отдельной миграцией; сейчас PostgreSQL/Supabase не используются.

Не включай `data/` и `.venv/` в архив исходников или Git. Для согласованной резервной копии работающей базы используй SQLite backup API (копировать один файл БД при включённом WAL недостаточно).

Документация используемых механизмов: [FastAPI CORS](https://fastapi.tiangolo.com/tutorial/cors/), [Python sqlite3](https://docs.python.org/3/library/sqlite3.html), [Python hashlib](https://docs.python.org/3/library/hashlib.html).


## API версии 3.0

Все маршруты ниже требуют Bearer-токен. Сервер определяет владельца из сессии; передавать `user_id` нельзя.

| Метод | Маршрут | Назначение |
|---|---|---|
| PATCH | `/api/favorites/{exercise_id}` | Тело `{ "saved": true }` добавляет в избранное, false удаляет |
| GET | `/api/me` | Дополнительно возвращает массив `favorites` |
| GET | `/api/notes` | Личные заметки, сначала недавно изменённые |
| POST | `/api/notes` | `id`, `title`, `body`, необязательный `exercise_id`; повтор ID с тем же содержимым не дублирует запись |
| PATCH | `/api/notes/{id}` | `title`, `body`, `exercise_id`, `revision`; конфликт версии — 409 |
| DELETE | `/api/notes/{id}?revision=N` | Удаление своей заметки с проверкой версии |
| GET | `/api/history?offset=0&limit=30` | `{items, total}`; limit от 1 до 100; выбранная строка, результат, время и полученные XP |

Схема SQLite 2 добавляет `favorites` и `notes` и индексы для чтения записей пользователя. Миграция автоматическая при старте и не удаляет прежние таблицы или данные. Удаление прогресса не удаляет заметки/избранное. API не предоставляет администраторские права.

Проверка: `PYTHONPATH=backend backend/.venv/bin/python -m pytest backend/tests -q` после установки `backend/requirements-dev.txt`. Всего 10 тестов API, включая прежние сценарии и новые операции с личными данными.
